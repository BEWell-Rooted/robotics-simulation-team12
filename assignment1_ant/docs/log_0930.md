## 판정 (2.4 규칙)

- **H1 음성**: 낙상은 "잘 걷다가 살짝 낮아진" 것이 아니라 **뒤집힘**. 임계를 낮춰도 거리 회복 없음
- **H2 음성(V1/V2) / 약한 양성(baseline)**: 분포 이동은 드문 spike뿐, clip 무효. zero는 baseline만 개선
- **H3 양성(부분), 대상 재정의**: 평면이 아닌 표면에서만 μ≥0.5에서 낙상 급증(baseline 5→43%). V1/V2는 μ0.2에서도 효과.
  BOX 대조 결과 박스 도형도 메시와 같으므로 원인은 "메시 삼각형" 특유가 아니라 **해석적 평면이 예외적으로 관대한 것**
- 종합: 실패 모드 = **평면이 아닌 표면에서, 마찰이 충분할 때(μ≥0.5), 뒤집힘(tip-over)**. 우리 학습 지형(V1/V2/V5)은 이미 메시인데도
  평지 구간에서 뒤집힘이 남음 → 물리 불일치가 아니라 **정책의 자세 안정성 약점**
- 2.4 규칙은 H1→V6, H2→V7만 정의 — **둘 다 음성이므로 계획서 그대로의 V6(높이 마진)·V7(힘 관측 노이즈)은 근거가 약함**

## 결정

- ✅ 형근 지시: 진단 후 새 학습 시작하지 않음 → 아래 "다음 행동"은 제안만
- ⚠ H3 격자는 지면 combine `multiply`로 실행 (로봇 μ 1.0 확인 → 유효 μ = 지면 μ로 해석 가능).
  조교식 `average`라면 유효 μ = (μ_지면 + 1)/2 → μ_지면 0.2~1.5는 유효 0.6~1.25에 해당
- ⚠ 선택 파이프라인은 선택 held-out(Boxes, Rails)과 보고 held-out(SlopedGrid, Pyramids)을 분리. 제출 후보 = `v2_s44@2999`

## 계획서 ↔ 코드 정정

1. **`feet_body_forces`는 발 "접촉력"이 아님**: `body_incoming_joint_wrench_b` = 부모→자식 링크의 **관절 반력 wrench**
   (부모 바디 좌표계). 접촉력·관성·관절력이 섞인 값 → 계획서 1.3, 2.2의 "접촉력", "원시 wrench" 표현 정정
2. **`RslRlSymmetryCfg`**: 위치는 `RslRlPpoAlgorithmCfg.symmetry_cfg` (runner가 아닌 algorithm cfg). 필드
   `use_data_augmentation`, `use_mirror_loss`, `data_augmentation_func(env, obs: TensorDict, actions) -> (obs, actions)`,
   `mirror_loss_coeff`. rsl-rl-lib 3.0.1 PPO가 지원 ✔ (증강 함수는 원본+반사를 이어 붙인 배치를 반환해야 함)
3. **지형 상대 높이(V6)**: `RayCasterCfg.mesh_prim_paths`는 **정적 메시 1개만** 지원("Currently, only a single static mesh").
   generator 지형(`/World/ground/terrain` 단일 메시)에는 쓸 수 있으나, 박스 도형·해석적 평면에는 못 씀.
   "지형 origin z 근사"는 타일 안 높이 변화(블록 ±h, 경사)를 반영 못 하므로 부적합
4. **CaT식 종료**: manager-based에서는 `DoneTerm(func=..., time_out=False)`로 구현 가능 — 계획서 설명과 일치
5. **H3 마찰 해석**: 계획서의 "메시 평지 μ × plane 같은 μ"는 지면 μ만 바꾸는 것이라, 결합 방식(average)에 따라 유효 μ가
   절반쯤으로 줄어듦 → 이번엔 multiply로 유효 μ를 직접 격자화 (위 결정 참조)
6. 계획서 1.1의 "저마찰 FlatIce baseline 5%"는 combine `min` 조건 — 이번 격자의 메시 μ0.2 baseline 5%와 일치
