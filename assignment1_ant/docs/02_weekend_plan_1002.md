## 0. 전제 (✅ 확인됨)

- 조교는 GitHub의 **우리 태스크 설정으로 로드**하고 지형(형태·지형 파라미터)만 바꿔 평가한다.
- 로봇 센서·물성치(P/D gain 등)·모델 구조·보상 함수는 자유롭게 설계 가능.
- 공식 자체 평가 = 학습에 안 쓴 자체 환경에서 `play_one_episode.py --seed 24 --num_envs 100`, 원래 Isaac-Ant-v0 보상 기준 mean/std를 PPT에 기입.
- 평가 기준은 reward 순위만이 아니라 **실험 설계 타당성·분석 논리·독창성**.

## 1. 평가 설계

| 용도 | 환경 | 쓰는 시점 |
|---|---|---|
| 분석 (변형 비교) | 기존 평가 12종 (`Isaac-Ant-Eval-*`), 256 envs × eval seed 3 | 매 학습 후 |
| 체크포인트 선택 | Boxes, Rails (선택용 held-out) | 후보 확정 시 |
| 보고용 held-out | SlopedGrid, Pyramids | 후보 확정 시 |
| **최종 테스트 (잠금)** | **`Isaac-Ant-Test-UnseenMix-v0`** — 타일마다 블록 w0.6 h±0.13(학습 범위 밖) / Pyramids / SlopedGrid / 원기둥(신규) / 평지 무작위, 지면 μ1.0 average | **월요일 오전 1회만** |

- PPT 수치는 공식 명령 그대로: `scripts/rsl_rl/play_one_episode.py --seed 24 --num_envs 100`.
  원본 IsaacLab_RS 스크립트와 차이는 `import ant_rough.tasks` 한 줄(우리 태스크 등록)뿐 — 보고서에 명시.
- 모든 평가 환경은 원래 Isaac-Ant-v0 보상 7항 → "보상 변경 팀은 원본 보상으로 출력" 조건 충족.
- **학습 예산**: 새 변형은 3000 iter 학습, 표는 두 개 — 예산 동일(model_1000 vs baseline model_999)과 확장(model_2999).
  대조군으로 baseline 3000 iter(평지) 1개 추가. 기존 V1~V5는 저장된 model_1000으로 재평가.

## 2. 실험

### 축 1 — 설계 타당성: 구조 고정, 환경만 변경 (모두 V2 차선 커리큘럼 기준, seed 42·43)

| 이름 | 변경 | 묻는 질문 | 출처 |
|---|---|---|---|
| A-noPromo | 차선 배치 동일, 승급·강등 없음, 시작 차선 무작위 | 승급·강등 커리큘럼 자체의 효과 | 팀원 3 |
| A-randDiff | 차선 유지, 타일 난이도 무작위, 승급·강등 없음 | 차선별 난이도 정렬의 효과 | 팀원 3 |
| V2S | V2 + 계단 (단일 변경) | 계단 추가가 계단 성능을 올리고 다른 지형을 유지하나 | 팀원 2 |
| V6′ | V2 + CaT 자세 제약 종료 (기울기 35°, roll/pitch 속도 3 rad/s, p_max 0.05) | 뒤집힘을 제약-종료로 줄이나 (페널티 V4와 대비) | 형근 1 |
| V10 | V2 + 수평 push + 초기 roll/pitch 랜덤화 + 완화된 기울기 페널티 | 회복 동작 학습이 뒤집힘을 줄이나 | 형근 1 |
| V11 | V2 + 레벨별 로봇 마찰 범위 (쉬운 차선 μ1±0.1 → 어려운 차선 1±0.8) | 마찰도 커리큘럼에 넣으면 나아지나 | 형근 2 |

분해 해석: V2 vs A-noPromo = 커리큘럼 효과, A-noPromo vs A-randDiff = 난이도 정렬 효과, A-randDiff vs V1 = 차선 배치 효과.

### 축 2 — 새로 열린 자유도: 로봇 쪽 변경 (V2 환경 기준)

| 이름 | 변경 | 비고 |
|---|---|---|
| V12 | 관측 히스토리(최근 몇 step) + 발 접촉 센서(`ContactSensor`) + 관측 정규화 | 지형 구현과 무관하게 동작 |
| V13 | V12 + LSTM 정책 (`ActorCriticRecurrent`) | |
| V14 | 발 재질 설계: 로봇 발 마찰·결합 방식(`min`) | ✅ 형근 승인. 발표에서 "발바닥 재질 설계"로 투명하게 설명 |
| V15 | PD 위치 제어 (P/D gain 설계) | 시간 되면 |

- **높이 스캔(RayCaster)은 쓰지 않는다**: 정적 메시 1개만 지원 → 조교 지형이 박스 prim이면 평가 시 에러.
- 트롯 보행 보상(팀원 아이디어)은 속도 저하 보고가 있어 보류, 여유 있으면 V2 위에 1 run.
