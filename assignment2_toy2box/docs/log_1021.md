## 다섯 줄 요약

- **결론:** 조교 파이프라인(요약 → replay → annotate → Mimic → BC 학습 시작)은 이 워크스테이션에서 모두 돈다. 다만 카메라 렌더링 모드(`--enable_cameras`)는 앱 시작 직후 크래시해서 replay 영상은 못 만들었고, 같은 모드를 켜는 `play.py --video`도 막힐 가능성이 크다.
- **실측:** 요약 20줄 조교 출력과 완전 일치 · annotate 20/20 export, 18분 11초 · Mimic 4 envs 성공 4/시도 6(67%), 2분 49초(앱 시작 포함) · BC 학습 2.9 s/epoch(epoch = 100 step, GPU를 다른 프로세스와 공유) · 저장 config `train.seed` 101.
- **막힌 것:** RTX 렌더러 크래시(`librtx.scenedb.plugin` → `createHydraEngine`), 4회 재현(래퍼·래퍼+DISPLAY·원본 스크립트·동시/단독 모두). 드라이버가 9/29 브리프의 580에서 595.99.02(10/08 갱신)로 바뀐 것이 가장 유력한 원인 후보(미확정). 또 `replay_demos.py`에 `--video` 인자 자체가 없다.
- **판단 질문:** `play.py --video`가 정말 크래시하는지 — 첫 체크포인트가 생기면 `--num_rollouts 1 --video`로 한 번 돌려 본다. 크래시하면 실패 분류(접근·파지·운반·배치)를 영상 없이 상태 기록으로 해야 한다.
- **다음 행동:** (1) 카메라 크래시 대처 결정(드라이버는 이 세션 권한 밖) (2) seed 111 지정 방법 결정(json이 추적 파일) (3) H2 텔레옵 녹화 1개 확인.

## 작업 설명

- **무엇을 왜:** 조교 시범 20개(hdf5)를 기준으로 과제 2 파이프라인 스크립트를 한 단계씩 짧게 실행해, 본 작업 전에 설치·인자·속도·함정을 확인했다. 장시간 작업은 실제 크기 대신 4개짜리 스모크로 대신하고 속도만 쟀다. 추적 파일은 고치지 않고, 필요한 것은 `assignment2_toy2box/tools/`에 따로 두었다.
- **흐름:** `toy2box_agibot.hdf5`(20 demo) → `summarize_demos.py`(분포 확인) / `replay_demos.py`(재생) → `annotate_demos.py --auto`(subtask 경계 표시, `_annotated.hdf5`) → `generate_dataset.py`(Mimic 증강, `_smoke_mimic_4.hdf5` + `_failed`) → `robomimic/train.py`(BC-RNN 학습) → (`play.py` 평가는 체크포인트가 없어 미실행)
- **리뷰 때 알아야 할 개념**
  - **Mimic subtask annotation:** 시범마다 "grasp 완료" 같은 subtask 끝 시점을 표시하는 것. Toy2Box는 subtask 2개(grasp 신호로 끝나는 집기, 마지막 놓기). `--auto`는 환경의 신호 함수로 자동 표시한다.
  - **Rel-Mimic 태스크:** 같은 Toy2Box 장면에 Mimic 데이터 생성용 인터페이스(eef 자세 변환·subtask 신호)를 붙인 별도 등록 ID. annotate·generate에만 쓰고 학습·평가는 `-v0`로 한다.
  - **BC-RNN(GMM):** 길이 10 관측 시퀀스를 LSTM(2층, 400)에 넣고 행동을 가우시안 혼합 5개로 내는 행동복제. Loss가 음수인 것은 음의 로그우도라서다. 이 config의 관측은 7개 키(상자·트럭 위치·자세, eef 위치·자세, 그리퍼) — joint_pos/vel은 안 쓴다.
