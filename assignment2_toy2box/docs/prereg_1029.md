## 0. 한 줄 요약

**원인 하나: Mimic 상자 구간의 SE(3) 재타깃팅이 만든 불필요한 운반 동작(손목 회전 + 우회 경로)이 들기 이후 실패를 만든다.** 확증 처치는 **A-T(상자 구간을 상자 위치만 따라가게)** 하나이고, 나머지 팔은 이 원인을 회전·경로·명령 크기로 나누거나(귀속) 경쟁 원인을 보는 데 쓴다. 등록한 실패 이동 예측으로는 A-T 효과가 약 +4–5%p 이고, 이 크기에서 확증(①) 확률은 0.17–0.28, 가장 흔한 결과는 "보류" 다(8절).

## 1. 진단 근거 (요약, 숫자는 진단 문서와 결과 파일 그대로)

- baseline(팀원 시범 20 → Mimic 500 → 조교 BC-RNN config): **66.0 ± 3.0%** (seed 101 63 · 111 69, A6000, 평가 seed 42 · 100회, 체크포인트 e2000). 같은 파이프라인 조교 시범 대조군 35.0 ± 2.0% (시작 상태로 짝지은 199쌍에서 Δ +30.7%p, 불일치 20 : 81).
- 실패 68건 중 **49건(72%)이 들기 이후**. 실패 원인 귀속(4절 규칙 (ii)): 충돌 19 · 스스로 놓음 19 · 미끄러짐 8 · 기타 3.
- 들기 이후 실패의 상태 지표: 들기 뒤 60 step 손목 각변위 `rot60_state` 성공 57–64° vs 실패 121–135°, 운반 중 손목 yaw 순변화 성공 32–35° vs 실패 58–63°, 상자 5 cm 이상 밂 실패 61% vs 성공 10%.
- 학습 데이터(`results/carry_metrics/data_human_mimic.csv`): 들린 동안 손목 yaw 순변화 사람 2.4° vs Mimic 38.4° (조교 시범 Mimic 21.8°). `rot60_state` 사람 24.3° vs Mimic 83.4°.
- **생성기 동작(트랙 A 가 찾고 코드로 확인):** `generation_select_src_per_arm=False`(기본값, `isaaclab/envs/mimic_env_cfg.py:67`) 라서 원본 시범은 subtask 1(트럭 기준 최근접)에서만 고르고 상자 구간에도 같은 원본을 쓴다(`data_generator.py:381–384`). 그래서 운반 중 회전 = 새 상자 yaw − 원본 상자 yaw 이고, 상자 yaw 는 ±180° 균일이라 맞춰지지 않는다. 성공 판정(`object_a_is_into_b`)은 위치만 본다 → 이 회전·우회는 과업에 필요 없다. (진단 §4 항목 5 · 서베이 §2.1 의 "구간별 원본 선택" 해석은 이것으로 정정했다.)

## 2. 가설

**H-A (1차).** 들기 이후 실패의 주원인은 Mimic 상자 구간 SE(3) 재타깃팅이 학습 데이터에 넣은 불필요한 운반 동작(원본–새 상자 yaw 차이만큼의 손목 회전과 그에 따른 우회 경로)이다. 상자 구간을 위치 평행이동만으로 만들면(A-T) 학습 데이터의 운반이 사람 시범처럼 바뀌고, 정책의 들기 이후 실패(특히 충돌 몫)가 줄어 성공률이 오른다.
- **반증 조건:** 데이터 게이트(3절)를 통과해 학습 데이터가 바뀌었는데도 A-T 가 5.2 의 ② 에 해당하면 H-A 를 기각한다.

**H_B (기전 분해, 같은 원인의 다른 경로).** 운반 동작의 해악이 "회전 상태" 가 아니라 Mimic 라벨이 실제 동작과 어긋난 큰 명령(목표 − 현재, 추적 지연 보정)에서 온다. 상태(회전 38°)는 그대로 두고 라벨만 실제 도달 자세로 바꾸면(B2) 들기 이후 실패가 준다.

**H_C (경쟁 원인).** 들기 이후 실패 중 스스로 놓음 일부는 GMM 이 매 step 소수 성분의 '열기'를 뽑아서 생긴다(운반·재타깃팅과 무관한 원인). 그리퍼만 혼합 다수결로 정하면(C3) 같은 기계의 위약(혼합 확률로 다시 뽑기) 대비 그 몫이 준다. 이 설계는 H_C 를 '지지' 할 수만 있고 기각할 수는 없다(5.4).

  **게이트를 못 넘으면:** 먼저 구현 오류를 찾는다. 오류를 찾아 고치면 다시 생성하고 7절 변경 기록에 남긴다. 오류가 없으면 그 팔은 "게이트 미통과" 로 보고하고 학습하지 않으며 큐의 다음 팔로 간다.
- **층화 (A-T · A-R):** 생성률이 baseline(44%)과 다르면 성공 필터가 남기는 장면 분포가 바뀐다(baseline 은 시작 거리 < 0.30 m 장면을 시도 13.7% → 성공 8.8% 로 덜 남긴다). 그래서 두 팔 모두 같은 도구·같은 seed 로 baseline 500 의 (시작 거리 [0, 0.30) [0.30, 0.35) [0.35, 0.40) [0.40, ∞) m × 상대 yaw 45° 간격 4칸) 히스토그램에 맞춰 500 을 뽑는다. A-T↔A-R 비교에는 위치 규칙 한 요인만 남는다. 층화 전 650 개의 분포와, 원본 선택 호출 히스토그램(`--src_log`; 시도 기준이라 실패·미완료 시도도 들어 있다)도 보고한다.
- **A-T 의 실패 이동 예측** (baseline → A-T, 귀속 (ii), 200 rollout 당): 충돌 19 → ≤ 12 · 스스로 놓음 19 → ≤ 16 (약한 예측) · **미끄러짐 8 ± 3 (불변 — 회전·우회와 연결 근거 없음)** · 기타 3 ± 3 · 들기 전 실패 19 → 음성 대조(5.2). **최소 예측 +4%p** 는 이 예측에서 나온다: 충돌 −7 의 대부분과 스스로 놓음 −3 의 일부가 성공으로 옮겨 간다고만 가정(전부 옮겨 가면 +5). 이전 판의 +9.5%p 는 독립 비교 2σ 잡음 폭을 옮긴 값이라 효과 예측이 아니었다(7절 변경 기록).
- **B2 의 감속 혼입:** baseline 들기 이후 실패는 운반 속도가 성공보다 빠르다(0.0133–0.0140 vs 0.0101–0.0103 m/step, `plan_B_speed_metrics.py`). B2 는 같은 시범을 open-loop 재생했을 때 운반이 약 6–9% 느려진다(같은 시범끼리 짝 비 0.915; 원본 10개 중앙값 0.0119 와 B2 6개 중앙값 0.0099 를 그대로 비교한 "−17%" 는 시범 묶음이 달라 쓰지 않는다). 운반 속도 차는 상태 매개 지표 `carry_speed` 로 보고한다. 예비로 B2-carry(운반 구간만 재라벨, md5 3d5fb287…044, 재생 8/10)를 둔다(큐 밖).
- 행동 라벨을 바꾸는 B2·B3' 는 "같은 성공 에피소드의 상태에 hindsight 로 행동만 다시 정의(축 C)" 로 서술한다. 사람 시범·Mimic 시범 수는 그대로다.
- **A-Y(yaw 고정) 대안은 쓰지 않는다:** 스모크에서 이미 box_push 26% 로 대안 게이트(≤ 20%)를 넘었다. A-R 을 못 돌리면 결론 범위를 "상자 구간 재타깃팅(회전 + 우회)" 까지로 줄인다.
- C-1mode 는 C3 가 5.4 의 '지지' 일 때만 돌린다. A6000 이 모자라면 가장 먼저 뺀다.

## 4. 지표 정의 (같은 스크립트를 모든 팔·데이터에)

- **범주:** `classify_failures.py` v3 (접근·파지·운반·배치 + 세부). **표적 묶음 = 운반 + 배치(들기 이후 실패)**. **HOLD(안 놓음류) = 세부 유형 `no_release` · `in_box_not_open` · `stall`**.
- **실패 원인 귀속 (ii) — 1차 규칙** (`carry_metrics.py` 의 `attr_ii`, 들기 이후 실패에만): 운반 창 [t_lift, t_loss + 5] 에서 상자 xy 이동 증가 > 5 cm 또는 상자 기울기 > 70° → **충돌**; 아니면 놓친 직후 그리퍼 명령이 열기 → **스스로 놓음**; 닫힘 → **미끄러짐**; 끝까지 들고 있음 → **기타**. 민감도로 (i) 창 t_loss ± 5, (iii) rollout 전체 상자 이동 > 5 cm 를 함께 보고. baseline: (ii) 19·19·8·3, (i) 2·28·14·5, (iii) 30·12·4·3.
- **상태 매개 지표 (팔 사이 기전 비교는 이것만, `paired_compare.py` 가 각 CSV 옆 `.carry.csv` 로 계산):** 건수 — `push_carry`(= 귀속 충돌), `box_push`(rollout 전체에서 상자 5 cm 이상 밂, 성공 rollout 포함 — 표적 묶음의 부분집합이 아니다), `low_approach`(approach_z < 0.15 m; baseline 에서 approach_z 가 있는 rollout 중 성공 9% (12/132) · 들기 이후 실패 38% (16/42) · 충돌 65% (11/17)), `self_release`, `hold`; 중앙값 — `approach_z`, `rot60_state`, `carry_yaw_net`, `xy30`, `carry_speed`, `carry_steps`.
- **조작 확인 지표 (게이트로만, 판정에 쓰지 않음):** 행동 기반 `rot60`, `carry_rot_cmd`, `carry_pos_cmd` — 라벨을 바꾸는 처치에서는 정의상 줄어든다.
- **짝짓기:** 같은 평가 seed 에서 시작 상태의 순서는 정책과 무관하지만, 정책이 트럭을 떨어뜨려 환경이 step 안에서 끝나면(`end_reason = dropped`) 자동 reset 이 난수를 하나 더 써서 그 뒤 rollout 의 시작 상태가 한 칸씩 밀린다. 그래서 `paired_compare.py` 는 **(학습 seed, 평가 seed, 시작 상태 6값)** 으로 짝짓고, 짝 없는 rollout 은 양쪽 dropped 수 합까지만 허용한다(넘으면 멈춤). 판정의 "400쌍" 은 이렇게 짝지은 수(보통 396–400)다. 군집 부트스트랩의 군집도 (평가 seed, 시작 상태)다.
- **비교 도구:** `paired_compare.py` — 정확 McNemar 양측·단측, 군집 부트스트랩 CI, 묶음 McNemar(`--bundle`, 묶음 열 `--bundle_col`), 하위 분석 `--min_d0`, 판정용 `--require_carry`(짝마다 `.carry.csv` 행이 있고 성공 값이 분류 CSV 와 같아야 함). null 띠 `null_enumerate.py` → `null_band.py`, 검정력 `power_sim.py`.

### 5.2 확증 팔 (A-T, B2, C-1mode) — 위에서부터 처음 맞는 하나

모두 **평가 seed 42 + 43 의 짝(약 400쌍)**, 대조는 baseline e2000. "띠" 는 5.1 의 json 값, "밖" 은 엄격히 큼.

| 단계 | 조건 |
| --- | --- |
| **① 효과** | 정확 McNemar 양측 p 를 **Holm 보정(3팔 고정, 돌리지 않은 팔은 p = 1)** 해 < 0.05 **그리고** Δ > max(6%p, 성공률 띠 6.09) = **6.09%p** **그리고** 학습 seed 별 Δ 가 모두 > 0 |
| **② 기각** | Δ 의 95% 상한(군집 부트스트랩) < 팔의 최소 예측(A-T +4, B2 +4; C-1mode 는 이 조건 없음), **또는** Δ ≤ −5%p 이고 보정 전 정확 McNemar 양측 p < 0.05 |
| **③ 방향 일치 (기술 등급 — 효과 미확인)** | Δ ≥ +5%p **그리고** 표적 묶음 단측 McNemar p < 0.10 **그리고** `box_push` 감소가 띠보다 큼: 100 × (json `mediators.box_push.diff`) / n < −6.0 (n = 400 이면 25건 이상 감소) **그리고** `low_approach` 증가가 띠 이하: 100 × `mediators.low_approach.diff` / n ≤ 7.11. ③ 은 원인 주장에 쓰지 않는다(6절 '+' 아님) |
| **④ 보류** | 나머지 전부 — "표본 한계로 판단 보류" |

- 주(막는 쪽 조건): 400쌍에서는 200쌍 띠가 너그러우므로, `low_approach` 증가가 띠의 절반(3.6/100)을 넘거나 들기 전 실패 증가가 띠의 절반(1.5/100)을 넘으면 판정과 함께 그 사실을 적는다.
- **음성 대조:** 들기 전 실패(접근+파지, baseline 19/200) 증가가 띠보다 크고(100 × (json `bundle_b − bundle_a`) / n > 3.03) 그 묶음의 짝 McNemar 양측 p < 0.05 이면(`--bundle approach,grasp`) "음성 대조 위반" 으로 따로 적는다.
- **baseline 체크포인트 민감도:** 확증 팔의 Δ 를 baseline e1900(A6000, 평가 seed 42 만 있음) 대비로도 보고한다(`--a results/noise_baseline/a6000_base_kgh500_s{101,111}_e1900_seed42.csv --b <팔>_s{101,111}_e2000_seed42.csv`). 6절의 덧붙임(H-A (나), H_B 같은 항목)에만 쓴다.
- **하위 분석(보고):** 시작 거리 ≥ 0.35 m 짝만의 Δ (`--min_d0 0.35`, 400쌍 전체에서; seed 42 에서는 146개).
- **체크포인트 민감도(보고, 큐 끝):** baseline · A-T · B2 의 e1800 · e1900 · e2000 을 평가 seed 42 로 평가해(baseline e1900 은 P0 에서 이미 있음) 같은 체크포인트끼리의 Δ(e1800 대 e1800, e1900 대 e1900, e2000 대 e2000)와 세 체크포인트를 합친 짝(약 600쌍)의 Δ 를 보고한다. 판정(①–④)은 바꾸지 않는다. 합친 Δ 가 ≤ 0 이면 6절 덧붙임 (나) 와 같이 "체크포인트 선택에 민감 — 약함" 을 덧붙인다. A6000 시간이 모자라면 B2 → A-T 순서로 뺀다.

### 5.3 귀속 팔 (A-R ↔ A-T, B3' ↔ B2) — 짝 팔끼리 직접, 평가 seed 42 + 43

- **동등:** 짝 팔 대비 Δ 의 90% CI(군집 부트스트랩)가 ±7%p 안. **차이:** 보정 전 정확 McNemar 양측 p < 0.05 (방향을 함께 적는다). 그 밖은 **구분 불가**. (모의, 400쌍: 참 차이 0 이면 동등 0.70, 참 차이 5%p 면 차이 0.45 — 8절 표.)
- 귀속 팔은 성공률 '효과' 를 주장하지 않는다. baseline 대비 값은 보고만 한다.

### 5.4 C3 ↔ 위약 (학습 seed 별 같은 Spark, 평가 seed 42, 약 200쌍)

- **판정 묶음 = 들기 이후 실패 중 비충돌 스스로 놓음** (`--bundle_col attr_ii --bundle self_release`, 소수 + 다수 열기 모두). 다수결 팔에서 "소수 성분 열기" 가 0 이 되는 것은 정의상 그렇다 → **조작 확인**으로만 쓴다.
- **지지:** C3 의 판정 묶음 감소가 띠보다 크고(100 × (json `bundle_a − bundle_b`) / n > 4.04; n = 200 이면 9건, n = 197–198 이면 8건 이상) **그리고** 그 묶음의 단측 McNemar p < 0.10 **그리고** HOLD 증가가 띠 이하(`--bundle_col subtype --bundle no_release,in_box_not_open,stall` 실행의 100 × (bundle_b − bundle_a) / n ≤ 2.03) **그리고** 성공률 Δ ≥ 0.
- C3 대 위약의 들기 전 실패 변화(`--bundle approach,grasp`)는 보고만 하고 판정을 바꾸지 않는다.
- **미지지:** 그 밖 전부. H_C 를 기각하지 않는다("판단 보류"). 트랙 C 의 예측(순감소 약 3건)으로는 미지지가 될 가능성이 높고, 미지지면 C-1mode 를 돌리지 않는다.
- 트랙 C 의 `attribute_c3.py` 와 공용 `carry_metrics.py` 는 baseline 49건 중 2건만 다르다: 트럭을 끝까지 쥔 채 상자를 민 s101 rollout_66 · s111 rollout_70 을 공용 도구는 충돌, C 도구는 '놓침 없음'으로 센다(트랙 C 집계 17 · 소수 6 · 다수 13 · 미끄러짐 8 · 기타 5). 판정은 공용 도구로 한다.

- **제출 후보 (점수 조건만, 원인 판정과 별개):** 팔마다 5.2 의 baseline e2000 대비 비교(json `delta_pp`, 짝 수가 팔마다 조금 달라 성공 수 대신 Δ 로 줄 세운다)를 쓴다. (1) ① 확증 팔 중 Δ 가 가장 큰 팔. - **체크포인트 사이 학습 잡음:** 시작 상태로 다시 짝지으면 같은 run 안에서도 체크포인트끼리 짝 McNemar 가 유의하게 갈린다 — gx10-3 s101 e1500 vs e2000: 97쌍 7 : 22, |Δ| 15.5%p, 양측 p = 0.008 (15쌍 중 2쌍이 p < 0.05; 10/28 진단의 "15쌍 모두 p ≥ 0.079" 는 번호 짝 때문이었다). 그래서 ① 의 p 값은 "두 체크포인트가 다르다" 를 뜻할 뿐, 학습 무작위성까지 넣은 처치 효과를 보장하지 않는다. 이를 막는 장치는 학습 seed 별 Δ > 0 과 Δ > 6.09%p 하한뿐이고, 하한은 이웃 체크포인트(e1800–e2000)에서 잰 것이다.
- **체크포인트 민감도 (처치 시작 전에 정함, 7절 변경 기록 14):** 위 학습 잡음 때문에 판정은 e2000 하나로 하되, 큐 끝에 baseline · A-T · B2 의 e1800 · e1900 을 평가 seed 42 로 더 돌려 **보고만** 한다(5.2 "체크포인트 민감도").

- 원인을 하나로 두지만 A-T 는 회전과 경로를 함께 바꾼다. 회전·경로·명령 크기의 몫은 A-R·B2·B3' 로만 나눌 수 있고, 귀속 결과가 "구분 불가" 면 결론 범위를 "상자 구간 재타깃팅(회전 + 우회)" 까지로 줄인다.
