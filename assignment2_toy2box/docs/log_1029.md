## 1. 한 일

1. 공용 지표 `tools/carry_metrics.py`: 데이터셋과 평가 기록에 같은 정의로 운반 구간 지표와 실패 원인 귀속(ii)을 계산한다. 상태 지표(`rot60_state`, `approach_z`, `push_carry`, `carry_yaw_net`)와 행동 지표(조작 확인용)를 나눴다.
2. 트랙 A·B·C fork: 각자 서베이 축에서 가설 → 한 요인 처치 → 구현 → 스모크 검증.
3. 교차 점검(검토자 3명 + 통합): 판정 기준의 검정력, 처치마다 섞여 들어오는 다른 요인, 지표 정의 불일치를 찾았다. 결과를 사전등록에 반영했다.
4. 공용 판정 도구 `tools/paired_compare.py` 를 다시 썼다: **(학습 seed, 평가 seed, 시작 상태 6값)** 으로 짝짓는다(5번 참고). 정확 McNemar(양측·단측), 시작 상태 군집 부트스트랩 CI, 묶음 McNemar(`--bundle`, `--bundle_col`), 하위 분석 `--min_d0`, 상태 매개 지표 차(각 CSV 옆 `.carry.csv`), 판정용 `--require_carry`, json 출력.
5. **짝짓기 오류를 찾아 고쳤다 (2차 점검):** 정책이 트럭을 떨어뜨려 환경이 step 안에서 끝나면(`end_reason = dropped`) 자동 reset 이 난수를 하나 더 써서 그 뒤 rollout 의 시작 상태가 한 칸씩 밀린다. 번호로 짝지으면 dropped 뒤의 rollout 이 모두 어긋난다(P0 s101 34쌍 · s111 5쌍, 조교 대조군 51쌍). 시작 상태로 다시 짝지어 P0·null 띠·검정력을 다시 계산했고, 10/28 진단의 조교 대조군(+31.0 → +30.7%p, 결론 같음)과 같은 run 체크포인트 15쌍(이전 "모두 p ≥ 0.079" → 2쌍 p < 0.05, e1500 vs e2000 p = 0.008)에 정정 메모를 달았다.
6. `run_baseline.sh`: 평가 seed 인자(`ESEED`), `OUTDIR`, 평가 seed 별 TMPDIR, 끝에 `carry_metrics` 실행, 종료 코드(0 성공 · 5 평가 실패(부분 기록은 .failed 로) · 6 분류 실패).
7. `classify_failures.py`: `empty_at_box` 를 트럭이 상자 밖일 때만 세게 고쳤다(사람 시범에서 95% 로 잘못 잡히던 것). 그래서 baseline CSV 3개의 이 열이 바뀌었다(범주는 그대로).
8. 잡음 기준선 P0: A6000 에서 같은 run 의 e1900 체크포인트(s101·s111)를 평가 seed 42 로 평가 → e2000 과 비교. Spark 에 남은 기록 5개로 처치 없는 비교를 모두 만들어 null 띠를 정했다(3절, `tools/null_enumerate.py` → `tools/null_band.py`). 검정력 모의 `tools/power_sim.py`.
9. 독립 점검 2회(각 점검자 3명 + 반박 검증 3명): 1차에서 판정 규칙의 허점 15건 남짓(잡음이 ③ 을 통과, A-T 최소 예측 근거 없음, 귀속 팔 '동등' 도달 불가, 트랙 C 판정 도구 없음 등), 2차에서 짝짓기 오류와 해석표·제출 규칙 문제를 찾았다. 모두 처치 결과 전에 고쳤다(사전등록 §7 변경 기록 1–12).

## 2. 트랙별 결과 (스모크)

**트랙 A — Mimic 상자 구간 재타깃팅 (1차 원인 H-A)**
- 코드로 확인: `generation_select_src_per_arm=False`(기본값) 라서 원본 시범은 트럭 구간에서만 고르고 상자 구간에도 같은 원본을 쓴다(`data_generator.py:381–384`). 운반 중 회전 = 새 상자 yaw − 원본 상자 yaw. 진단 §4 항목 5 · 서베이 §2.1 에 정정 메모를 달았다.
- `tools/generate_yawhold.py` (`--translate` / `--rotworld` / `--yawhold`, `--src_log`): 모드 없이 돌리면 baseline 샤드와 bit 단위로 같다.
- 스모크 30개(중앙값): 손목 yaw 파지→상자 위 baseline 47.5° → A-T 13.0° · A-R 13.4°, xy30 0.212 → A-T 0.089 · A-R 0.299 m, 상자 밂 16% → 6% · 17%, 생성 성공률 44% → 89% · 58%.
- `tools/plan_A_stratify.py`: A-T·A-R 은 생성률이 baseline 과 달라 성공 필터가 남기는 장면 분포가 달라진다. 그래서 두 팔 모두 baseline 의 (시작 거리 4 × 상대 yaw 4) 히스토그램에 맞춰 500개를 결정적으로 뽑는다(칸마다 ±2, 못 맞추면 종료 코드 2).
- `tools/plan_A_smoke_check.py check AT|AR`: 사전등록 3절 게이트를 문턱과 비교(스모크 두 팔 모두 통과, `results/plan_A/check_smoke_1029.txt`).

**트랙 B — 행동 라벨 표현 (기전 분해 H_B)**
- `tools/relabel_actions.py`: B2 = (4 step 뒤 실제 손끝 자세 − 현재), B3' = 원본 방향 × B2 크기, B2-carry = 운반 구간만 B2. 관측·상태·그리퍼 열은 원본과 bit 동일(자동 검사 통과).
- 라벨–실제 이동 방향 cos(운반 구간): 원본 0.59 → B2 1.00, 라벨 크기/실제 이동 2.31 → 1.00.
- open-loop 재생(gx10-3, 같은 시범 10개, 버그 점검용): 원본 9/10 · B2 4/10 · B3' 0/10 · B2-carry 8/10. B2 의 접근 초반 편차 1.33 cm 로 좌표계 버그는 아니다.
- B2 는 같은 시범끼리 운반이 약 6–9% 느리다(짝 비 0.915; 처음 적은 "−17%" 는 시범 묶음이 달라 쓰지 않는다). baseline 의 들기 이후 실패는 운반이 성공보다 빠르므로(0.0133–0.0140 vs 0.0101–0.0103 m/step), 감속은 `carry_speed` 차로 함께 보고한다.

**트랙 C — 정책 구조 (경쟁 원인 H_C)**
- `tools/plan_C/play_gripmix.py`: 평가 때 그리퍼만 혼합 다수결(C3) / 위약(혼합 P(open) 으로 다시 뽑기). `sample` 모드는 baseline 기록과 행동까지 bit 동일.
- 오프라인: 들기 직후 큰 회전은 GMM 모드 샘플링에서 오지 않는다(혼합 평균/실행 비율 0.99–1.00).
- C3 판정 묶음(비충돌 스스로 놓음 전체)은 A6000 baseline 19건 · Spark 12건이다. 같은 run 체크포인트끼리도 이 묶음이 19 → 11 로 움직여서 null 띠(100개당 4.04)를 적용했다. 트랙 C 의 예측 순감소는 약 3건이라 "미지지" 가 나올 가능성이 높다. 소수 열기 6건(Spark 8건)은 조작 확인용.
- C-1mode(`num_modes` 5→1)는 `play.py` 경로 그대로 평가된다(100 epoch 스모크 4회 정상 실행).

## 4. 사전등록의 최종 판정 설계 (요약 — 숫자는 `docs/prereg_1029.md`)

- 확증 팔 A-T · B2 (· 조건부 C-1mode): 평가 seed 42 + 43 의 짝(약 400쌍) 대 baseline e2000. ① Holm-3 McNemar p < 0.05 · Δ > 6.09%p · 학습 seed 별 Δ > 0 / ② 95% 상한 < 최소 예측(A-T +4, B2 +4) 또는 Δ ≤ −5 이고 p < 0.05 / ③ 방향 일치(기술 등급: Δ ≥ 5 · 묶음 단측 p < 0.10 · `box_push` 가 띠 밖으로 감소 · `low_approach` 증가 ≤ 띠) / ④ 보류.
- 귀속 팔 A-R ↔ A-T, B3' ↔ B2: 400쌍, 동등(90% CI ±7%p 안) · 차이(p < 0.05) · 구분 불가.
- C3 ↔ 위약(Spark, 200쌍): 지지 / 미지지 (H_C 는 기각하지 않는다).
- 해석표는 가설별(H-A · H_B · H_C), 제출은 점수 조건만(학습 seed 101 의 짝 Δ > 0 포함).
